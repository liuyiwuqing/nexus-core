# 消息路由与定向测试 · CONSOLE-07

V16 默认 `broadcast`，所有旧入库入口继续向启用设备广播。创建路由不会自动切换模式。管理员在路由页显式切换为 `rules` 后，新消息只建立匹配路由的投递；无匹配或所有规则停用时仍保存消息，但不建立投递。旧消息/投递不重新路由，设备禁用、离线、TTL、重试及设备端 DND 语义保持。

## 条件与优先级

规则定义包括名称、启停、精确来源/事件类型（`*` 全部）、关键词或受限正则、目标设备数组、可选优先级，以及时区/每日时间窗。关键词大小写敏感，在标题与正文中查找；正则只接受文字、首尾锚点及至多一次 `.*`，拒绝分组、回溯、其他量词和控制字符，避免不受限的正则执行。开始包含、截止不包含，支持跨午夜；开始等于截止非法，两个时间均空表示全天。

按规则创建时间和 UUID 固定顺序合并目标，多条匹配同一设备只建一条投递，首个命中决定该设备的优先级；未指定时保留来源消息优先级。仅选择已登记且当前启用的设备，离线也可入队。优先级在入库事务保存到 `deliveries.priority_override`，worker 读取最终值；修改/删除规则不改变已有投递。Schema v1 与设备消息信封字段不变，服务端模板随后独立实现。

## API

- `GET /api/v1/routing`：模式/版本、未删除规则列表。
- `PUT /routing/policy`：`{mode:broadcast|rules,expectedVersion}`；新目标与原版本固定，相同目标在原版本加一时可确认重试；其他版本 409。
- `PUT /routing/rules/{UUID}`：`{expectedVersion,definition}`。首次版本 0，客户端固定 UUID；更新使用观察版本。相同有效定义可确认原版本重试，冲突 409。所有字段经过服务器验证，设备必须存在；新行的并发身份由主键保护。
- `DELETE /routing/rules/{UUID}?expectedVersion=…`：标记删除并加版本，相同原版本重试 204。单条 GET 仍能核对 `deleted`，不复活已删除 ID；旧投递不撤回。
- `POST /routing/preview`：传入现有 `MessageInput`，只返回模式与匹配设备/优先级，不创建消息或投递。
- `POST /routing/test`：`{requestKey:UUID,deviceIds,title,content,priority}`；只向显式选择的启用设备建立投递，独立于广播/规则模式。201 新建，200 同键重放，改变参数/目标 409。固定请求键的事务锁防止并发请求绕过比较；来源标记 `manual-test`、metadata `test=true`，不会伪造 Halo 公开评论。现有 `/messages` 管理入口契约不变。

接口均沿用管理员鉴权。路由定义、目标列表只在服务端保存，无任意 shell、URL 或设备凭据操作。重试/刷新不会主动重发未知动作；页面草稿、原 UUID/版本、定向测试身份及未确认模式目标在 App 当前内存中跨导航保留，退出清除。模式重试固定原目标，不能将“响应丢失后已成功切换”再次反向切换。关闭/刷新整个页面后先读回核对。
