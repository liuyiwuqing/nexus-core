# 自动化规则编辑 · CONSOLE-09-A

2026-11-14。现有每日提醒可编辑名称、时间、时区、标题和正文；公开评论分析可编辑名称。规则 ID、类型、执行历史与原创建幂等键保留。规则必须已停用且没有正在入队的任务，保存后保持停用，由用户核对后重新启用。本项不新增数据库迁移，也不提供删除、测试运行或通用条件/动作。新前端须与本项 API 同包发布；旧服务端缺少编辑接口与版本参数。

## HTTP 契约

沿用 `/api/v1` 管理员 Bearer、32 KiB 请求体上限和 `no-store`。旧创建与重放契约见[工具与规则创建](console-operations.md)。

| 接口 | 行为 |
| --- | --- |
| `GET /automation/rules` | 原 `{items}`；每条增加 `canEdit`、`editBlock` |
| `GET /automation/rules/{id}` | 读取同一规则定义，包含 ID、名称、类型、参数、启停、版本及编辑门控；未知 ID 404 |
| `PUT /automation/rules/{id}` | `{expectedVersion,name,localTime?,zone?,title?,content?}`；成功 200 返回当前完整规则 |
| `PUT /automation/rules/{id}/enabled` | 原 `{enabled}` 增加可选 `expectedVersion`；成功仍为 204 |

`expectedVersion` 为正整数，编辑时必填。名称非空、最多 80 字符；每日时间为 `HH:mm`、时区须由 `ZoneId` 识别，标题非空且最多 160 字符、正文非空且最多 8192 字符。非法时区明确返回 400，不再抛成 500。编辑不能提交或更改 `trigger`、`action`；类型沿用原规则。评论规则只有名称参与有效定义。

编辑时锁定规则行，然后核对版本、停用状态及是否存在任何版本的 `executing` 任务：

| 条件 | 结果 |
| --- | --- |
| 当前版本等于预期，定义有变化且允许编辑 | 原行更新，版本只增 1，保持停用 |
| 当前版本等于预期，定义未变化且允许编辑 | 200，版本不变 |
| 当前版本恰为预期加 1，定义完全相同且允许编辑 | 200，确认当前结果，版本不再增加 |
| 其他版本不匹配 | 409 `automation_version_conflict` |
| 已启用 | 409 `rule_enabled` |
| 存在正在入队的任务 | 409 `rule_execution_in_progress` |
| 参数错误、未知 ID、未鉴权/其他作用域 | 400、404、401，无写入 |

相同保存的重试只在上述当前状态满足条件时获得确认，不是无限期保存的操作账本。之后若有其他编辑或启停，旧请求仍可能返回 409，应只读核对当前定义；不能盲目改成最新版本自动重发。`canEdit` 是读取时的提示，不能替代写入时的事务校验。

页面启停也提交观察到的版本；相同目标启停重试只在原版本或原版本加 1 且目标已匹配时成功。旧客户端省略版本仍保持原行为，因此不具有新页面的版本保护。

## 执行与历史

- 编辑采用“停用 → 等待在途入队完成 → 编辑 → 核对并重新启用”。正在入队的任务不会被强制取消或改参数；因此无需给旧任务猜测或补造新的参数快照。
- 定义变化时取消仍为 `pending` 的旧任务，记 `rule_edited`；已入队、失败等历史保留，版本不重写。旧版本失败任务不能以新参数重试。原停用已取消的任务保持原状态。
- 已生成的消息、投递、分析队列及其正文不因改规则撤回或重写。历史中的名称仍是规则当前名称，`ruleVersion` 才是执行版本；不是不可变的名称/参数审计档案。
- 每日事件继续以 `规则 ID + 本地日期` 去重，不含版本。当天事件一旦生成，即使随后被取消或修改时间，重新启用也不补造同日期事件；尚未生成时仍按原有两小时窗口处理。修改时区可能改变本地日期，不提供任意滚动 24 小时只触发一次的保证。
- 评论规则重新启用时只处理启用之后的新公开事件，不重放修改前的旧评论。已有来源公开性和分析授权检查保持。

## 页面与未知结果

在规则卡片选择“编辑”。已启用或存在在途任务时禁用并说明原因；编辑期间关闭本页其他规则编辑/启停入口。原生必填/长度/时间控件校验继续适用。

草稿与原版本保留在 App 当前内存，轮询、刷新列表和切换导航不会覆盖。保存中冻结输入并防止重复提交。成功确认 ID、类型、版本和有效定义后关闭编辑，焦点回到原规则操作；没有自动启用。

网络、408/5xx 或无效确认保留原 URL、版本和参数，“重试原版本修改”只发送原请求。首次明确 4xx 拒绝释放草稿修正；一旦原结果未知，后续拒绝也不能证明首次未保存，因此继续保留原请求。

“核对当前规则”只发 GET。当前定义与待确认目标匹配时结束核对；这只确认当前状态，不声称谁提交了变更。不同则在草稿旁显示服务端名称、时间和正文，只有用户显式选择“放弃草稿并载入当前版本”才替换草稿及版本。关闭编辑不撤回可能已经保存的修改。

读取失败隐藏旧列表动作、禁用保存并保留草稿，读回失败不显示虚构定义。退出/401 清除编辑会话，迟到的保存或读回不能恢复登录；不写浏览器存储。刷新或关闭整页后，应先核对规则列表。
