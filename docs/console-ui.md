# 管理台界面与组件约定

2026-11-16 · CONSOLE-14。保持 Vue 3 / TypeScript / Vite 与随 JAR 发布的方式，使用 Naive UI 2.45.3 和 `@lucide/vue` 1.73.0。字体和图标不依赖外部 CDN，版本由 package-lock 固定。

## 界面与使用

- 十二个入口分为“日常”“消息与自动化”“系统”，管理员、操作员、只读角色的可见范围沿用原约定；默认仍进入消息页。
- 桌面保留侧栏，可在 208px 与 64px（`--sidebar-w-collapsed`）间折叠，偏好写入 `nexus-sidebar-collapsed`；760px 以下使用可滚动抽屉，支持 Escape、焦点约束和关闭后返回菜单按钮。选择页面后关闭抽屉并聚焦页面标题。
- 消息保留列表/详情联动，手机选择消息后显示详情并提供返回；默认只显示消息状态与来源标识，收件时间收在“更多筛选”，已应用时间条件在折叠按钮上显示数量。展开/收起保留草稿，逆序日期提交时自动展开并报错。筛选与导出分开组织，“导出”内保留元数据下载和管理员正文确认。未应用的筛选、读取错误、空结果与导出中继续禁止导出。
- 设备卡片统一在线标记、接收开关、设置和固件入口；登记、重命名的版本核对、禁用新消息和 OTA 确认流程保留。界面状态不代表设备已收到或完成操作。设备页页头下方的工具条依次是名称/ID 搜索（300ms 防抖，回车立即生效）、状态、排序（创建时间/名称/最近连接，含升降序）与每页条数（12/24/48/96）；搜索清空或任一条件变化都回到第一页，参数均由服务端执行。
- 所有表单、输入、下拉、多选、日期/时间、数字、勾选、滑杆和文件选择使用 Naive UI；提交校验沿用原来的必填、长度、格式、范围和步长，不改请求字段、时区转换或服务端分页。
- 登录令牌仍仅保存在页面内存。消息、工具、规则和模板的未知结果、原请求身份、草稿与只读核对保持；关闭或刷新页面的恢复边界不变。

## 样式基线（CONSOLE-15）

`style.css` 的 `:root` 为唯一 token 来源，`theme.ts` 与之逐值对应（颜色/圆角/字阶/描边/焦点环）；诊断、度量对照与未落地清单见 [console-ui-refinement.md](console-ui-refinement.md)。

- 操作按钮全部使用 `NButton`，含导航、消息列表项、图表缩放重置、历史评论导入及导出入口；颜色、描边、悬停和焦点由 Naive 主题决定，页面 CSS 只负责排版。普通操作使用同一种默认描边按钮：高度 34px、圆角 8px、字号 13px、横向内距 12px；主提交与当前选中项使用 `type="primary"`，危险动作使用 `type="error"`。图标操作使用 34px 方形按钮。导航和消息行保留各自的选中语义，数字输入框内部加减键沿用组件尺寸；操作区不再混用无边框、不同大小或圆形按钮。`.primary/.secondary/.text-button/.compact` 定义为 0，不新增样式。红色仅用于"删除 / 撤销 / 永久失效"三类不可回退动作，全站 5 处。
- 当前表格、卡片和浮层的密度规范见 [CONSOLE-24](#表格卡片与浮层console-24)。
- 表格卡片化以 `data-label` 为开关（`:has(td[data-label])`），未标注的表格回退横向滚动。`dl>div` 默认两列网格，指标条用 `display:block` 覆盖。
- 跨仓浏览器断言按行为写，不按条数写。

## 取数与加载（CONSOLE-16）

- 轮询只取当前标签页渲染的接口（`App.vue` 的 `tabResources`）；SSE 失效额外补 `devices`，因为顶栏"设备视图"是外壳级依赖；顶栏刷新、错误重试、登录走 `allResources`。新增页面必须同时登记 `tabResources`，否则该页数据不会轮询。
- `refresh()` 的第二个参数是集合而不是布尔；`loading` 只在实际取数据时置位，纯 `status` 探测不占用它。筛选/搜索的守卫用 `busy || exporting`，竞态统一由 `readGeneration` 负责。
- 面板一律通过 `src/panels.ts` 的 `asyncPanel(name)` 引入，不直接写 `defineAsyncComponent(() => import(...))`；新增面板要同时登记 `loaders` 与 `tabPanels`，否则意图预取拿不到。
- `focusContent()` 按有限次轮询等 `.content h1`：面板是异步挂载的，一次 `nextTick` 不足以拿到标题。

## 状态提示（CONSOLE-18）

"操作结果尚未确认"这类提示一律走 `StatusNote`：`tone="warn"`（需处理，带底色与圆点）、`tone="danger"`（失败）、`tone="info"`（只读说明，等同原来的灰字脚注），需要重试按钮时放进 `#actions` 插槽。根元素保留 `.scope-note` 类名，跨仓断言以它为钩子。

不要再用 `.inline-error` 表达"未确认"：红色留给确定失败。新增提示若只是补充说明，用 `tone="info"` 或直接写 `.scope-note`，避免满屏状态带。

`tone ≠ info` 的根元素是 `role="alert"` + `aria-atomic="true"`，`info` 保持 `role="status"`。这不是语义偏好：warn/danger 只在提交失败那一刻插入，`polite` 会排在加载中之类的播报之后被吞掉，而这档信息是"不看就不能继续"的。同一事实只能出现一段提示 —— 提交未知时不要再单独渲染一句红字，把事实并进提示正文。

根元素带 `tabindex="-1"` 并 `defineExpose({ focus })`：提交期间点按钮会 `disabled`，Chrome 立刻把焦点丢到 `body`，调用方在失败分支 `await nextTick(); note.value?.focus()` 把它接回来，键盘用户不必从头 Tab。

## 焦点与展开态（CONSOLE-19）

- 内联面板（`DeviceManagementPanel`、`RemoteOtaPanel`）根节点是 `tabindex="-1"`，打开时脚本 `focus()`，并监听 `@keydown.esc` 关闭。「设置与升级」互斥，再点同一按钮收起：同开会让 Tab 从升级按钮串进设置面板，卡内还会出现两组同名的刷新/收起。
- 焦点环只在真正落焦时画（`.management-panel:focus`）。常驻 `outline` 会把内联进卡片的面板又框成第二个盒子，也让人误以为那是误留的焦点环。
- `html { scroll-padding-top }` = `--topbar-h + --toolbar-h + 8px`：脚本 `focus()` 与锚点滚动都停在两根吸顶条之下，不被遮住。
- 设备设置展开后，上方是设备摘要和动作，下方设置/遥测面板占满卡片宽度（CONSOLE-21）；CONSOLE-23 把常用设置放在状态历史前方，高级设置与历史分别折叠。避免长面板旁边留下空列；`≥900px` 仅把摘要与动作并排，760px 以下表单单列。
- 标题与右侧动作使用 `flex-wrap` 与 `h2 { flex:1 1 auto; min-width:18ch }`，长名称自然换行。内嵌面板标题保持较小一级，不重复设备名。
- 提示上带动作按钮的 `StatusNote`（「已核对，开始新的签发」「放弃重试并只读核对」「关闭模板草稿」）会把提示连同按钮一起卸载，Chrome 随即把焦点丢给 `body`。这类动作必须在 click 处理里 `await nextTick()` 后把焦点交给**下一步真正要用的元素**，按动作语义选，不要统一套路：权限页给名称输入框（下一步就是填名签发）、来源页给本区标题（动作本身就是"只读核对"，从标题往下读）、模板页给重开入口「创建模板」（表单整块卸载）。只在用户主动点掉这条路径转移焦点 —— 轮询/SSE 让提示自然消失时不要抢焦点，会打断正在输入的人。`NButton` 不暴露 `focus()`，需要按 id 取 DOM（与设备页同一做法）。
- `--topbar-h` 统一为 56px；滚动定位与吸顶反馈使用同一个 token。

## 设备状态历史（TELEMETRY-02）

- 「设置与状态」把两个时间语义分开：实时徽标只来自 `GET .../management` 的 `fresh`（90 秒内收到新遥测），文案为「实时快照 / 快照已过期」并带原生 `title` 说明；历史区块只写「状态历史 · 来自设备已上报的遥测」，不标「实时」，脚注说明最后一条不代表设备在线。
- 图表为无依赖内联 SVG：`freeHeap` 实线用 `--accent`，`minFreeHeap` 虚线用 `--info`；相邻点跨度超过 1.8 个桶就断线，缺失区间不补零、不连直线。悬停与左右方向键显示时间、可用/最小 KB，`role="img"` 与 `aria-label` 提供读屏摘要。
- 范围固定为 1 小时/6 小时/24 小时/7 天，分别映射 `1m/5m/15m/1h`；切换即请求，不保留旧范围的点。历史每 60 秒刷新，快照仍每 3 秒轮询，两者不合并。
- 图表外层 `.chart-scroll` 横向滚动、SVG `min-width:560px`：窄屏在图内滚动而不是压缩字号，也不让图表撑破文档宽度。

## 状态历史指标切换（TELEMETRY-03 / TELEMETRY-05 / TELEMETRY-07）

- 时间范围下方是内存/音量/未读/音频/网络指标组，默认内存；切换只换本地序列，不重新请求历史。时间范围变化仍立即重查并清空旧点，指标选择在范围内保留。
- 取数口径：内存为 `freeHeap`/`minFreeHeap`（KB，实线/虚线），音量为 `volume`（`%`），未读为 `unread`（条），音频为 `audioUnderruns`（次），网络为 `wifiRssi`（dBm，负值正常显示）。单序列指标只画实线，`--info` 虚线只属于内存的启动以来最小值。
- 音频视图在 `audioFaulted=true` 的桶上叠加 `--danger` 圆点，图例出现「音频异常」，悬停该点写明；`audioUnderruns` 为 `null` 的桶不画点，断线规则仍是 1.8 倍桶宽。网络视图在 `wifiRssi` 为 `null` 的桶断开。
- 计数与百分比指标的下界钳在 0，全 0 时刻度不出现负值；网络指标保留负刻度。`aria-label` 摘要按当前指标说明采样数、最后值与异常样本数。
- 实时快照的指标条在设备上报网络信息时显示「网络」一项（SSID · 地址 · 信道 · 信道宽度 · RSSI dBm · BSSID，缺失段自动省略），上报过断线时再显示「上次断线」（原因名称 · 相对时间，未知码显示数字）；都未上报时整项省略，不发额外的网络探测请求。
- 设备卡片在存在遥测网络信息时，于「最近连接」下方追加「Wi-Fi」一行：SSID（无 SSID 时退回地址）、地址、信号 dBm 与该样本的相对时间；都没有时整行省略，列表接口用 `LEFT JOIN LATERAL` 取最近一条带地址或 SSID 的样本，不逐台补查。

## 断线历史列表（TELEMETRY-08）

- 设备上报过断线原因、或已读取到断线记录时，状态历史下方出现「最近断线」折叠区：每条显示断线时刻（设备未对时时退回记录时刻并说明「尚未对时」）、原因名称与记录时间；未收录的原因码直接显示数字。最多 20 条，来自只读的 `GET .../telemetry/disconnects`，不触发设备动作。
- 打开设备面板、点「刷新状态」或设备上报新的断线时刻时重读；既无断线原因、列表也为空的设备不渲染该区块，避免空状态噪声。列表只覆盖保留期内的历史样本，最后一条不代表设备当前在线。

## 状态历史缩放与导出（TELEMETRY-04）

- 图内拖拽选区放大时间窗口，松开即生效；缩放只放大已取回并聚合的桶，不重新请求历史，纵轴按窗口内采样自适应。缩放后图上方出现「重置缩放」，双击图表也可恢复；每分钟刷新时窗口仍在查询范围内则保留缩放。
- 「导出 CSV」导出当前范围的全部桶，不受当前指标限制：26 列含采样/接收时间、样本数、固件与配置版本、音量/亮度/静音/免打扰/未读、内存四值、音频欠载、推理/显示最长耗时、音频异常、Wi-Fi IP/信号/SSID/信道/信道宽度/BSSID 与断线原因/时间；UTF-8 BOM + CRLF，Excel 直接打开不乱码。文件名为 `telemetry-<设备>-<范围>-<UTC 时间>.csv`，无采样点或读取失败时按钮禁用。
- 图表用 `clipPath` 裁掉缩放窗口外的线段、故障点与游标，避免边缘堆叠；时间跨度小于 3 小时时轴标签精确到秒。

## 主题、折叠与升级阶段（2026-11-16）

- 明暗主题沿用 `colorMode.ts`：唯一真相是 `<html data-theme>`，`watch(isDark)` 同步 `color-scheme` meta；首次跟随系统，手动切换后写 `nexus-color-mode`。CSS token 与 `theme.ts` 两套覆盖都只读这一处，组件不得自行判断深浅。深色下 Naive 浮层、原生日期/滚动条与图表配色都已随 `color-scheme` 切换。
- 侧栏折叠只收起视觉文字：`.nav-label`、分组标题和角色标记 `display:none`，文字仍留在 DOM 供读屏与测试使用；图标按钮补 `aria-label` 与原生 `title`。底部“退出登录”和“折叠/展开”在折叠态都是 30×30 圆形按钮、竖向 4px 间距，与导航图标对齐；`≤760px` 抽屉里隐藏折叠按钮（`.mobile-navigation .sidebar-collapse`），避免出现两套开合控制。
- `.skip-link` 配合 `<main tabindex="-1">`：Tab 首站是“跳到主内容”，跳转后焦点落在内容区且不画常驻焦点环。
- Naive 浮层（Dropdown/Popover）统一 12px 圆角与 `--floating-shadow`，Tooltip 8px；两者都由 `theme.ts` 的 `Palette` 驱动，不在页面里单独覆盖。
- OTA 阶段条只由设备上报的 `observation.state` 推导：`pending/sent/accepted`→准备、`installing`→安装、`pending_reboot/rebooting`→重启、`verifying`→核验、`healthy`→完成。失败、结果未确认或未知状态整条不渲染，不猜进度；写入进度只在 `installing` 且拿到 `target.imageSize` 时按 `writtenBytes/imageSize` 画，缺镜像大小就不画，不用假动画代替设备确认。
- 顶栏与侧栏继续使用原生 `title` 做简短悬停说明。CONSOLE-21 为 `vueuc` 浮层与虚拟列表增加局部 nonce 适配；新增浮层仍需按正式 CSP 实测，不能仅以 Vite 开发模式能打开为通过。

## 样式守卫（CONSOLE-17）

`npm run check` = `vue-tsc --noEmit && node scripts/check-tokens.mjs`（单跑 `npm run check:tokens`）。五条规则：

0. `style.css` 与组件 `<style>` 块的花括号必须成对 —— 多一个 `}` 时 `vue-tsc` 与下面四条全过，只有 lightningcss 在 build 阶段报 `Invalid empty selector`，坏 CSS 能一路走到构建才炸；
1. `style.css` 的 hex 只允许出现在 `:root` 定义里；
2. 组件的 `<style>` 块里不允许出现任何 hex；
3. `var(--x)` 必须已在 `:root` 定义（带 fallback 也算）；
4. 定义过的 token 必须有人引用。

失败即退出 1，`run_local.py build` 与 21 个跨仓 UI 脚本都会因此中断。CONSOLE-17 那轮删掉 5 个死 token（`--accent-hover`、`--accent-pressed`、`--info`、`--info-soft`、`--radius-pill`）；`--radius-pill` 已为 OTA 阶段胶囊和进度条重新引入。CONSOLE-21 移除三个原生控件专用 token，CONSOLE-22 随原生按钮样式删除 `--accent-soft`，当前 74 个。

`.primary/.secondary/.text-button/.compact` 保持零字节定义：视觉由 Naive 主题与 `type` 决定（仅导航和消息行用 `secondary`/`quaternary` 表达选中），这几个类只作模板与断言的语义 hook，不做样式扩展。

## 修改位置

`frontend/src/theme.ts` 管理 Naive UI 主题；`style.css` 管理布局与间距；`navigation.ts` 保存导航分组和图标；`ConsoleNavigation.vue` 复用角色导航；`ConsoleShell.vue` 管理桌面框架和移动抽屉。App 继续拥有请求、权限会话与待确认提交，界面组件不另建 API 或持久化副本。

颜色以现有深绿为强调色，正文使用深色中性色；动作层级、字段边框、面板和间距统一。移动适配改变布局，保留字段、操作后果和错误信息；尊重减少动态效果偏好。

## 静态页 CSP

Naive UI 会生成样式节点。`GET /` 和 `GET /index.html` 为每次响应生成独立 24 字节随机 nonce，写入页面 meta 与 `style-src 'self' 'nonce-…'`，并返回 `Cache-Control: no-store`。原 `default-src 'self'`、禁止嵌套、base-uri/form-action 与 API 鉴权保留，没有增加 unsafe-inline 或外部脚本来源。

`NConfigProvider` 开启 `inlineThemeDisabled`，通过其公开 `styleMountTarget` 为 Naive 挂载的样式节点加 nonce。`vueuc` 的 binder/虚拟列表绕过该配置，因此 Vite 仅把 `vueuc/es/shared/index.js` 的 `./cssr` 导出路由到 `vueucStyles.ts`，保留节点的 mount 上下文并复用同一个样式目标；不修改全局 DOM 方法，也不放宽 CSP。`css-render` 固定为锁文件已有的 0.15.14，没有引入另一套组件库。依赖升级必须复跑严格 CSP 下的真实菜单/日历/时间/上传交互。开发用 Vite 没有服务端 nonce 时使用默认样式目标。正式 JAR 必须同时包含新 index/JS/CSS 与配套过滤器；不能只替换其中一部分。
