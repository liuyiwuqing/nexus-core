# 工具与规则创建的故障处理 · CONSOLE-12-A

工具请求和自动化规则在 HTTP 结果未知时保留同一提交编号与参数，显式重试不会另建一条。工具仍经过原有白名单、参数绑定和打开应用确认；规则仍默认停用。此项补齐现有页面的故障处理，不扩展工具能力或自动化条件/动作。

## 创建与重试

工具继续使用原有 `POST /api/v1/tool-jobs` 的 `requestKey` 和服务端去重。此前页面每次点击都生成新键，保存后响应丢失会产生第二条请求；现在同一逻辑提交保留原键、工具和参数，收到匹配的有效确认后才释放。

规则的管理员 `POST /api/v1/automation/rules` 增加可选 UUID `requestKey`：

| 请求 | 结果 |
| --- | --- |
| 新键和合法定义 | 201 `{ruleId}`，新规则默认停用 |
| 相同键、相同有效定义 | 200 原 `{ruleId}`，不重置启停/版本，不生成新规则 |
| 相同键、不同有效定义 | 409 `idempotency_conflict` |
| 不带键或键为 null | 保持旧调用：每次合法请求独立创建，返回 201 |
| 非法 UUID/规则、未鉴权 | 保持 400 / 401，无写入 |

V14 增加可空唯一 `create_request_key` 和原始创建定义的 SHA-256 指纹。指纹使用稳定字段顺序，覆盖名称、触发条件、动作及其有效执行参数；不根据后来变化的启停/版本计算。并发 INSERT 由数据库唯一约束合并，重复请求只读回原 ID；键和指纹不出现在规则列表。现有规则保留原 ID/名称/启停/版本，两个新字段为 null，不补造旧提交身份。

两种创建均在网络、408/5xx、解码或无效确认时冻结原提交，允许显式重试；首次明确 4xx 拒绝才释放编辑。若原结果已经未知，后续拒绝也不能证明第一次没有保存，因此仍保留原编号。401 清除会话。刷新列表和轮询只读，不自动重放创建、确认、取消或重试。

待确认内容留在 App 当前页面内存，切换导航可恢复；退出/401 清除，迟到响应不能恢复会话。不写 localStorage/sessionStorage。刷新或关闭页面后不能恢复编号，此时应先核对工具/规则列表。部署须保持本轮前端、API 和 V14 配套，旧服务端不支持新规则键。

## 页面与动作

- 工具/自动化有独立刷新，区分加载、成功空结果和失败；手动刷新清除旧操作，后台读取期间禁用提交/状态动作，失败隐藏旧能力、请求、规则和执行记录。读取失败不会被解释为 Bridge 未启用。
- 全局后台刷新只清理已恢复的读取错误；操作错误留给用户显式刷新核对或下一次操作，不被轮询自动清空。错误提示的“重试”和顶部刷新只读核对列表，不重发原操作。
- Bridge 未启用/不可用或目标未在白名单时，禁止新建工具请求；打开应用必须先创建请求，再确认绑定的目标。已有 unknown 作业只核对原请求，不重新执行。
- 工具审计独立显示加载/空/失败；关闭或切换后，迟到的审计结果/错误不污染其他记录或整页。
- AI 未配置时不能启用评论分析规则，仍可停用已启用规则。执行重试只提供给当前启用、版本匹配的失败任务；入队状态不表示设备已经显示或用户已读。

启停、重试、确认、取消沿用原 URL/服务端状态条件。请求中禁用重复点击；响应未知时重新读取当前列表核对，不自动重发动作。该页面的读取快照不是并发动作的最终授权，服务端仍校验当前状态。

后续 CONSOLE-09-A 新增[停用后规则编辑](console-automation-editing.md)与单条定义读回，并为新页面启停增加可选版本校验；原无版本客户端、创建键和未知结果处理保持兼容。规则删除、测试运行和通用条件/动作仍未实现。
