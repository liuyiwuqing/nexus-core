# 实时更新、设备视图与接入引导 · CONSOLE-11

## SSE 与回退

`GET /api/v1/events` 使用 Bearer 请求头，不能把令牌放 URL、Cookie 或浏览器持久存储。响应为 `text/event-stream`，`Cache-Control:no-store`、`X-Accel-Buffering:no`，事件数据版本固定 `schemaVersion:1`：

- `ready`：连接建立，返回当前读取模型的 revision，客户端重新读取。
- `invalidate`：服务端观察到已提交的设备列表/连接、消息收件/已读/清理或投递历史变化，通知客户端重新读取。
- `heartbeat`：连接仍可用，无业务副作用。
- `unauthorized`：下一次服务器检查时令牌已到期/撤销，客户端清除会话。

服务端每 2 秒共享一次数据库快照指纹，仅有客户端时读取；每实例最多 32 条连接，每条 25 秒后重连，逐次检查现有管理员/独立角色令牌。revision 是读取模型的变化提示，不是业务事件号、审计日志或跨请求一致性承诺；不持久化事件，也不支持历史补放。任何重连都重新读取当前状态，不能从一个事件推导设备已显示。

浏览器使用 fetch 流式读取，支持分块/CRLF、有界 64KiB 解析缓冲；1/2/4…最多 30 秒重连。流健康时根读取模型保留 15 秒安全刷新；断线回到现有 5 秒轮询。读取失败、隐藏页、正在写入或导出时不因提示重放操作，页面重新可见时只读刷新。其他模块已有的独立轮询仍保留，不宣称本项为所有数据提供完整变更订阅。

反向代理应允许流式响应，保留 `X-Accel-Buffering:no` 语义，连接超时至少 30 秒。反向代理不支持流、临时 503 或连接中断时会自动轮询。HTTPS、实际 1Panel/OpenResty 网络及代理行为仍需目标机验收。

## 设备视图与首次引导

顶部设备选择器跳转并筛选设备视图，不暗中改变消息广播或定向测试目标。选“全部设备”恢复原设备列表；所有写动作仍明确选择目标。未登记设备时首登自动显示接入引导，其余情况可手动打开/收起，不写永久完成标记。

`GET /api/v1/setup` 只读返回注册设备、是否曾观察到设备连接、是否已有接收/展示回执，以及 CORE 与 Broker 连接状态；`credentialsProvisioned:"unknown"` 明确服务端不能由登记推断设备专属凭据已配置。引导顺序为登记 → 从部署端配置专属连接 → 显式定向测试 → 投递时间线核对，不自动生成/展示密码、烧录或发送消息。operator/viewer 的登记与凭据步骤说明由管理员处理，不提供越权操作。
